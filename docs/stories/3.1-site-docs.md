# Story 3.1 — Site Documentacao

## Descricao

Como usuario, quero acessar site com documentacao completa dos componentes, previews ao vivo e exemplos, para entender como usar WI.UI no meu projeto.

## Status: Pending

## Paginas

- **Home** — hero, features, componentes destaque, CTA
- **Docs** — sidebar navigation, MDX pages por componente
- **Components** — grid visual de todos componentes com preview
- **Themes** — galeria de temas prontos
- **Playground** — link pro customizer (Story 4.1)

## Criterios de Aceite

- [ ] Fumadocs configurado e funcionando
- [ ] Home page com hero + features + CTA
- [ ] Documentacao MDX por componente com:
  - Descricao
  - Preview interativo (live code)
  - Props table
  - Exemplos de uso
  - Copy button (codigo)
- [ ] Sidebar navegavel por categoria (Base, FOMO, Animation)
- [ ] Search funcional (ctrl+k)
- [ ] Responsivo mobile
- [ ] Dark/light mode
- [ ] SEO (meta tags, og:image)
- [ ] Performance (LCP < 2s)

## Tarefas Tecnicas

1. Instalar e configurar Fumadocs:
   - `pnpm add fumadocs-core fumadocs-ui fumadocs-mdx`
   - Configurar content source (packages/registry/*/docs.mdx)
   - Setup MDX components (Preview, PropsTable, CodeBlock)
2. Criar layout docs:
   - `src/app/docs/layout.tsx` (sidebar)
   - `src/app/docs/[[...slug]]/page.tsx` (MDX render)
3. Implementar home page:
   - Hero section (titulo, descricao, CTA install)
   - Features grid (copy-paste, FOMO, themes, CLI)
   - Componentes showcase (preview cards)
   - Footer
4. Criar MDX components customizados:
   - `<ComponentPreview>` — render ao vivo do componente
   - `<PropsTable>` — tabela de props auto-gerada
   - `<InstallBlock>` — bloco com comando CLI
5. Configurar search (Fumadocs search built-in)
6. Dark mode (next-themes + Tailwind dark:)
7. SEO: metadata API Next.js, og:image generation
8. Deploy verificar performance
