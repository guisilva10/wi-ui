# Story 2.1 — Componentes FOMO/Conversao

## Descricao

Como usuario da lib, quero componentes focados em conversao e urgencia, para aumentar taxa de conversao das minhas landing pages sem montar do zero.

## Status: Pending

## Componentes (7)

1. **Countdown Timer** — data alvo, formato customizavel, callback ao expirar, urgencia visual
2. **Social Proof Popup** — "Fulano comprou X", animacao entrada, queue de notificacoes, auto-dismiss
3. **Scarcity Badge** — "Restam X vagas", pulso animado, threshold cores (verde/amarelo/vermelho)
4. **Testimonial Card** — foto, nome, cargo, texto, rating stars, variantes (minimal, full, video)
5. **Pricing Card** — planos, preco riscado, badge popular, CTA, feature list, toggle mensal/anual
6. **Progress Bar** — animada, porcentagem, label, variantes (linear, circular), meta visual
7. **CTA Button** — hover effects, urgencia (pulse, glow), micro-copy embaixo, loading state

## Criterios de Aceite

- [ ] 7 componentes implementados em `packages/registry/fomo/`
- [ ] Cada componente: TypeScript, Tailwind v4, acessivel
- [ ] Zero runtime deps pesadas (motion apenas onde necessario)
- [ ] Animacoes CSS puro quando possivel (keyframes Tailwind)
- [ ] Configuravel (textos, cores, timings via props)
- [ ] Metadata + docs MDX por componente
- [ ] Previews no site
- [ ] Testes basicos

## Tarefas Tecnicas

1. Estrutura no registry:
   ```
   packages/registry/fomo/countdown-timer/
   ├── countdown-timer.tsx
   ├── use-countdown.ts (hook)
   ├── meta.json
   └── docs.mdx
   ```
2. Implementar cada componente:
   - Countdown: hook useCountdown + display component
   - Social Proof: queue system, animacao CSS, portal
   - Scarcity: threshold logic, pulse CSS animation
   - Testimonial: layout variants, star rating sub-component
   - Pricing: toggle state, price formatting, feature checkmarks
   - Progress: CSS animation, percentage calc, labels
   - CTA: hover states, pulse keyframe, micro-copy slot
3. Criar hooks reutilizaveis onde necessario (useCountdown, useQueue)
4. Testes (render, timers, interactions)
5. Docs MDX com exemplos de uso real

## Dependencias

- Story 1.1 (componentes base existem — CTA usa Button, etc.)
- Story 1.3 (registry API pra servir)

## Notas

- DIFERENCIAL PRINCIPAL da lib — nenhuma outra faz isso
- Componentes devem ser opinionated em conversao mas customizaveis em visual
- Exemplos de uso real nas docs (landing page SaaS, e-commerce, curso)
