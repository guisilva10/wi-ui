# Story 1.1 — Componentes Base (UI)

## Descricao

Como usuario da lib, quero ter componentes UI base disponiveis no registry, para usar via CLI no meu projeto.

## Status: Pending

## Componentes (8)

1. **Button** — variantes: default, destructive, outline, ghost, link. Sizes: sm, md, lg, icon
2. **Input** — text, email, password, search. States: default, error, disabled
3. **Card** — Card, CardHeader, CardTitle, CardDescription, CardContent, CardFooter
4. **Badge** — variantes: default, secondary, destructive, outline
5. **Dialog** — modal acessivel, overlay, close button, composable
6. **Toast** — success, error, warning, info. Auto-dismiss, action button
7. **Skeleton** — pulse animation, composable shapes
8. **Avatar** — imagem + fallback initials, sizes: sm, md, lg

## Criterios de Aceite

- [ ] 8 componentes implementados em `packages/registry/`
- [ ] Cada componente: TypeScript, Tailwind v4, acessivel (aria)
- [ ] Zero runtime deps (so React + Tailwind)
- [ ] Cada componente com arquivo de metadata (name, description, deps, files)
- [ ] Previews funcionando no site
- [ ] Testes basicos (render, interactions)
- [ ] Documentacao MDX por componente

## Tarefas Tecnicas

1. Definir estrutura componente no registry:
   ```
   packages/registry/ui/button/
   ├── button.tsx
   ├── button.test.tsx
   ├── meta.json (name, category, deps, files)
   └── docs.mdx
   ```
2. Implementar cada componente com:
   - Props tipadas (interface)
   - Variantes via class-variance-authority (cva) ou cn manual
   - Ref forwarding
   - Aria attributes
3. Criar utility `cn()` (clsx + tailwind-merge) em shared
4. Escrever testes (Vitest + Testing Library)
5. Criar MDX docs com exemplos
6. Registrar no index do registry

## Dependencias

- Story 0.2 (estrutura monorepo)

## Notas

- Inspiracao: shadcn/ui (qualidade) + radix primitives (acessibilidade)
- Nao usar radix diretamente — componentes proprios pra controle total
- cva ou cn manual: decidir consistencia no primeiro componente
